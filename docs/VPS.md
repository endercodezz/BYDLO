# Свой сервер VLESS + REALITY

Первая версия: отдельный установщик для запуска **по SSH на собственном Linux VPS**.
Из приложения SSH не выполняется. Реальное подключение ещё требует ручной проверки.

Требования: чистый Debian 12+/Ubuntu 22.04+ с systemd 247+, Python 3.9+, root,
x86_64 или aarch64, публичный адрес и свободный входящий TCP-порт (по умолчанию 443).
В панели VPS и собственном firewall заранее разрешите этот порт. Установщик не меняет
firewall, DNS, маршруты, SSH и сторонние службы; не запускайте его на рабочем компьютере
или сервере с существующей сетевой конфигурацией, от которой зависит доступ.
При занятом порте служба завершится с ошибкой — выбирайте свободный порт.

1. Скопируйте `scripts/vps/install_reality.py` из проверенного checkout BYDLO на VPS:

   ```bash
   scp scripts/vps/install_reality.py root@VPS:/root/install_reality.py
   ssh root@VPS
   ```

2. Выберите доступный с VPS сайт с TLS 1.3 и HTTP/2 для REALITY. Он должен принимать
   выбранное SNI и не перенаправлять его на другой домен. Подставьте публичный адрес
   VPS и выбранное имя вместо примеров:

   ```bash
   python3 /root/install_reality.py --install --address 203.0.113.10 --sni example.com --port 443
   ```

   `example.com` здесь — заполнитель, не рекомендация готового REALITY-сайта.
   Установщик скачивает закреплённый Xray-core 26.10.21, проверяет SHA-256,
   генерирует UUID/X25519/short ID, проверяет конфигурацию и создаёт только
   `bydlo-reality.service`. Существующие установки не перезаписываются.
   Данные находятся в `/opt/bydlo-reality`, служба использует DynamicUser и
   systemd LoadCredential: конфигурация с приватным ключом читается из защищённого
   каталога credentials, исходные секреты и ссылка доступны только root.

3. Скопируйте выданную `vless://`-ссылку. **Это данные доступа к серверу**:
   не публикуйте её, QR-код, приватный ключ и конфигурацию. Закройте доступ
   посторонних к терминалу и его журналам. Копия ссылки:

   ```bash
   sudo cat /opt/bydlo-reality/client-link.txt
   ```

4. В BYDLO откройте «Добавить сервер», вставьте ссылку, проверьте адрес, порт,
   SNI, REALITY и сохраните. Выберите профиль и подключитесь. Это ручной этап:
   установщик не проверяет обход блокировок и не подключает клиент автоматически.

Диагностика на VPS: `systemctl status bydlo-reality` и
`journalctl -u bydlo-reality --no-pager -n 50`. Не отправляйте журналы без проверки
на секреты. Неудачная установка сохраняет свои файлы для диагностики.
Для удаления **на VPS**: остановите и отключите `bydlo-reality.service`, удалите
его unit и `/opt/bydlo-reality`, затем выполните `systemctl daemon-reload`.
Пользовательские правила firewall удаляются отдельно владельцем.

Изолированные проверки для разработки (без установки): загрузите `scripts/env.*`,
затем `python -m unittest discover -s scripts/vps -p 'test_*.py'`.
Проверки не запускают Xray и systemctl. Полный сценарий установка → импорт →
реальное подключение вынесен в отдельную issue ручной проверки. Пункт
«Развернуть свой» в UI добавляется после этой проверки.

Основа конфигурации — [пример Xray-core VLESS + REALITY](https://github.com/XTLS/Xray-examples/tree/main/VLESS-TCP-XTLS-Vision-REALITY).
Лицензия Xray-core — MPL-2.0; исходники: [XTLS/Xray-core](https://github.com/XTLS/Xray-core).
Идея пары клиент + сервер: [unbihex](https://github.com/crystalmasta/unbihex).
