## Права администратора

В «Настройки → Дополнительно» доступна необязательная [привилегированная служба](PRIVILEGED_HELPER.md): Windows service, systemd на Linux и launchd на macOS. UI остаётся без повышенных прав, служба запускает комплектные TUN sing-box, Zapret, AmneziaWG и OpenVPN. Статус всех трёх реализаций — 🧪: установку/удаление и реальную сеть проверяет мейнтейнер. Пользовательские конфиги, плагины, цепочки и внешние наборы правил через службу не поддерживаются; OpenVPN принимает ограниченное безопасное подмножество директив и требует отдельно установленный DCO-драйвер на Windows. Нативный WireGuard через wg-quick/wireguard.exe остаётся в прежнем режиме повышения.

Без службы сохраняется прежнее поведение: кнопка «Перезапустить от администратора» на Windows (`asInvoker` до явного повышения), запуск с root на Linux/macOS. Установка и удаление службы требуют отдельного системного подтверждения администратора; в Mock Mode и при блокировке разработки эти действия запрещены.

Для AmneziaWG нужны права администратора/root; Linux использует `/dev/net/tun`, `ip` и, при DNS в профиле,
`resolvectl` с systemd-resolved. На Linux без systemd-resolved настройка DNS этим адаптером пока не поддерживается.
Маршруты по умолчанию добавляются как две половины `/1`, исходные default routes сохраняются; маршрут к каждому
серверу закрепляется до включения туннеля. Изменения привязаны к отдельному `bydlo-awg` и журналу восстановления.
Хуки `PreUp/PostUp/PreDown/PostDown`, `Table`, `SaveConfig` и DNS-домены в `.conf` отклоняются.
На macOS AmneziaWG использует отдельный utun, временные маршруты и DNS активных сетевых служб. Журнал нужен для восстановления после сбоя. Реальное подключение проверяется владельцем вручную.
Хост сообщает выделенное имя `utunN` через `WG_TUN_NAME_FILE`; при отсутствии файла запуск
прерывается с очисткой. Маршруты IPv4/IPv6 по умолчанию разделяются на два `/1`, исходные
default routes не заменяются. При восстановлении DNS и маршруты к серверу меняются только
если они всё ещё соответствуют записанным настройкам BYDLO. Неудачное восстановление
сохраняет журнал `amnezia-macos-network.json`; повторите отключение для новой попытки.
До повторной очистки после ошибки подготовки блокировка журнала остаётся у текущей сессии.

OpenVPN 2.7 не поддерживает Wintun. BYDLO использует DCO; TAP-профили и несовместимые с DCO параметры
на Windows не поддерживаются этой встроенной конфигурацией. Драйвер и адаптер остаются установленными после выхода;
для удаления используется диспетчер устройств Windows. Установка не выполняется при подключении, в Mock Mode или safety lock.
Unix-сборка отключает LZO/LZ4, PKCS#11, плагины и DCO: OpenSSL и libcap-ng не нужно доустанавливать,
но libc и системные инструменты настройки сети остаются зависимостями ОС. Автоматическое применение pushed DNS
для OpenVPN на Unix пока не реализовано; используйте настроенный системный DNS.
Нативные подключения AmneziaWG/OpenVPN и установка DCO требуют ручной проверки владельцем, автоматические тесты используют фейки.

При импорте и перед каждым запуском OpenVPN (напрямую или через службу) действует общая проверка
безопасного подмножества директив. Внешние обработчики, плагины, загрузка модулей, вложенные `config`,
управляющие сокеты и произвольные файлы вывода запрещены. Сертификаты и ключи должны быть встроены
в `.ovpn`; внешний `auth-user-pass` запрещён — файл учётных данных создаёт само приложение.
Ранее сохранённые профили также проверяются перед запуском; небезопасный конфиг отклоняется до записи
рабочего `.ovpn` и запуска процесса.

## Цепочки прокси (relay)

Цепочка — упорядоченный список сохранённых серверов: трафик входит в первый и выходит из последнего.
Сборка — только на движках с поддержкой relay: sing-box соединяет outbound'ы через `detour`,
Xray — через `proxySettings`. Нативные WireGuard / AmneziaWG / OpenVPN, Zapret и TgWsProxy
в цепочке не участвуют: выбор такого звена или движка завершается `NotImplemented`
(`error.chain.engine`), приложение честно сообщает об этом.

| Функция | sing-box | Xray-core |
|---|---|---|
| Цепочка из 2–5 звеньев | 🧪 (`detour` между outbound/endpoint) | 🧪 (`proxySettings` между outbound; выходной — первый outbound по умолчанию) |
| WARP как звено цепочки | 🧪 (endpoint с `detour`, включая `reserved`) | ❌ (Xray не поддерживает WireGuard-звено) |
| Проверка соединения цепочки целиком | 🧪 (сквозная проверка через локальный прокси) | 🧪 (так же) |

При сохранении отклоняются: меньше двух звеньев, больше пяти, несуществующие серверы,
повторы (защита от петель) и принудительный движок вне sing-box/Xray. Удаление сервера
отцепляет его от цепочек; цепочки короче двух звеньев удаляются. Цепочки входят в
зашифрованный бэкап; устаревшие (со ссылкой на отсутствующие серверы) при восстановлении
пропускаются.

## Cloudflare WARP (итог исследования и реализация)

WARP основан на WireGuard. Регистрация выполняется через неофициальный клиентский API
Cloudflare `https://api.cloudflareclient.com/<версия>/reg` — те же endpoints, что использует
[wgcf](https://github.com/ViRb3/wgcf) (MIT; код wgcf в BYDLO не копируется, арифметика X25519
реализована самостоятельно по RFC 7748).

Итог исследования (закрывает исследовательскую часть задачи):

- API недокументирован и версионируется (`v0a…`); BYDLO закрепляет проверенную версию
  и не угадывает новые. Заголовки клиента (`User-Agent`, `CF-Client-Version`) обязательны,
  иначе сервер отвечает 403.
- Регистрация подтверждает Terms of Service Cloudflare меткой времени; официальный клиент
  и wgcf не аффилированы с BYDLO.
- Лицензия wgcf (MIT) допускает повторную реализацию протокола; упоминание и ссылка
  сохранены в `THIRD_PARTY_NOTICES.md`.
- Стабильность не гарантирована Cloudflare: регистрация — только по явному нажатию,
  автоматических попыток и фоновых вызовов нет; сбои показываются локализованной ошибкой.

Реализация:

| Функция | Windows | Linux | macOS | Android |
|---|---|---|---|---|
| Регистрация WARP по кнопке («Серверы» → Cloudflare WARP) | 🧪 | 🧪 | 🧪 | 🗓 |
| Подключение WARP-профиля (WireGuard через sing-box, ключи в `ISecretStore`) | 🧪 | 🧪 | 🧪 | 🗓 |
| WARP как звено цепочки | 🧪 (см. выше) | 🧪 | 🧪 | 🗓 |

Сгенерированный профиль — обычный сервер WireGuard (`engage.cloudflareclient.com:2408`,
`reserved` из `client_id`, если сервер его вернул): его можно подключать, включать в цепочки
и бэкапить как любой другой. Account id, токен и лицензия хранятся в `ISecretStore`
и никогда не попадают в журнал (`LogRedactor`). Клиент API покрыт модульными тестами
с фейковым HTTP; живую регистрацию проверяет мейнтейнер вручную.

## Ограничения Zapret

- Windows ARM64: в закреплённом Flowseal-архиве есть только x64 WinDivert. Эмуляция x64 не заменяет ARM64 kernel driver; BYDLO честно возвращает `NotImplemented`.
- Linux: нужен root, установленный `nft` и поддержка NFQUEUE в ядре. Используется только nftables; fallback на iptables отсутствует. Очередь 21770 и метка 0x40000000 зарезервированы для BYDLO.
- macOS: нужен root, свободный TCP-порт 21771, активные стандартные `com.apple/*` filter/rdr anchors. BYDLO не переписывает `pf.conf`. Только локальный IPv4 TCP 80/443; UDP/QUIC, IPv6, трафик root и игровой фильтр не поддерживаются.
- Нативные пресеты BYDLO используют публичные опции upstream; они не копируются из проектов без лицензии и не эквивалентны всем стратегиям Flowseal.
- Пользовательские списки находятся в `<data>/zapret/lists/`. Приоритет установки: встроенная исправная копия → управляемая → папка пользователя. При обновлении приложения пользовательские списки не перезаписываются.
- Работоспособность обхода в конкретной сети проверяет мейнтейнер вручную.

## Kill switch

Опция выключена по умолчанию. В **Настройки → Дополнительно** прочитайте предупреждение,
подтвердите его и включите «Блокировать интернет при отключении VPN». Опция применяется
при следующем подключении **TUN через sing-box**. Для других движков подключение TUN с этой
опцией отклоняется; режим локального прокси не меняется.

Отдельный процесс sing-box держит `auto_route` + `strict_route` и передаёт интернет-трафик
в локальный SOCKS5-порт транспортного процесса. При падении транспорта и во время его
перезапуска TUN остаётся активным; прямого резервного выхода в интернет нет. После
исчерпания попыток переподключения блокировка сохраняется до явного отключения.
LAN (IPv4, IPv6 link-local и ULA) и mesh-диапазоны исключаются согласно настройкам маршрутизации.
Прямые домены, CIDR, процессы и режим «только выбранные домены» при этом игнорируются.

Удалённый DNS сохраняет выбранный транспорт (UDP, TCP, HTTPS, TLS или QUIC) и работает
только через прокси. Адрес DNS-сервера должен быть IP-адресом: системный DNS, доменное
имя с отдельным bootstrap-разрешением и направление «напрямую» отклоняются явной ошибкой
до запуска процессов. В DNS-конфиге TUN нет прямого или системного резервного сервера.
Раздельные правила DNS в TUN не применяются; все его запросы идут на удалённый DNS.
Транспортный процесс сохраняет адреса, транспорты и направления DNS для своих запросов.

Кнопка **«Выключить kill switch и отключиться»** доступна в настройках без раскрытия
дополнительных параметров. Обычное отключение и закрытие окна также останавливают TUN.
После сбоя BYDLO следующий запуск пытается завершить только оставшийся TUN-процесс из
журнала BYDLO с проверкой PID, имени образа и времени запуска. Если не хватает прав,
нужен перезапуск с прежними правами и эта же кнопка либо очистка оставшихся процессов.
Чужие VPN и mesh-клиенты не затрагиваются. Mock-режим и safety lock запрещают такую очистку.

**Ограничение:** защита действует, пока жив отдельный TUN-процесс. Его собственный сбой,
принудительное завершение или изменение маршрутов сторонним ПО может открыть прямой доступ.
Это не постоянная блокировка на уровне ОС. Сетевое поведение и снятие маршрутов после
аварии требуют ручной проверки на каждой ОС; агенты и CI её не выполняют.

Схема: [TUN / strict_route](https://sing-box.sagernet.org/configuration/inbound/tun/),
[SOCKS outbound](https://sing-box.sagernet.org/configuration/outbound/socks/).

Автоподбор Zapret доступен в «Инструменты → Zapret»: Windows — аргументы winws из найденных BAT,
Linux/macOS — нативные пресеты. Стандартные HTTP/TLS-проверки Test Zapret 1.10.3 перенесены
в BYDLO; интерактивный скрипт не запускается. Проверка только по явному действию пользователя,
с правами администратора/root, curl и возможностью отмены. Область измерений и ограничения:
[автоподбор в TESTING.md](TESTING.md#автоподбор-zapret).

### Готовые режимы маршрутизации

На главной можно выбрать режим, а на странице «Маршрутизация» — страну и загрузить закреплённые наборы правил. Режим «Только сайты, заблокированные в России» использует список RunetFreedom. Режим «Всё, кроме местных сайтов» использует домены и IP-диапазоны SagerNet для России или Китая. Ручные исключения и блокировки применяются перед наборами. Настройки вступают в силу при следующем подключении.

Региональные режимы доступны в sing-box. При включённой аварийной блокировке TUN выберите обычный режим. BYDLO сверяет SHA-256 наборов при загрузке и перед подключением.

В разделе «Дополнительно» можно добавить упорядоченные правила, поменять их местами и импортировать или экспортировать JSON. Для sing-box указывайте тег закреплённого набора, например `geosite-ru` или `geoip-cn`. Для Xray указывайте код из geo-файла, например `category-ru` или `cn`. Кнопка загрузки на той же странице проверяет нужные geo-файлы до обновления кеша.

В «Дополнительно → Источники наборов правил» показаны встроенные источники и редактор своих источников: тег, закреплённый HTTPS-адрес, SHA-256 и предел размера (до 64 МиБ). Для sing-box источник содержит бинарный `.srs`; его тег используется в условии Geosite или GeoIP и в DNS-правилах. Имена `geosite.dat` и `geoip.dat` предназначены для замены соответствующих geo-файлов Xray. Встроенные теги sing-box менять нельзя. URL и хеш обновляются вручную; фоновой загрузки нет.

Загрузка выполняется только кнопкой. До публикации файла проверяются предел размера и SHA-256; ошибка, отмена или обрыв сохраняют предыдущий проверенный файл. Подключение читает только кеш и повторно проверяет размер и хеш, без автоматической загрузки. Изменение источника на новый хеш требует загрузки новой версии до переподключения. Отдельные файлы обновляются независимо. Уже запущенное подключение продолжает использовать прежнюю конфигурацию.

Экспорт JSON содержит `Rules` и `Sources`; порядок правил сохраняется. Импорт принимает также прежний JSON-массив правил, проверяет данные целиком до изменения редактора и не загружает источники. После импорта нажмите «Сохранить». Размер импортируемого файла ограничен 1 МиБ. Полная резервная копия также сохраняет источники; при объединении одноимённых источников приоритет у текущих настроек.

Общие geo-условия переводятся между движками: Geosite `cn` / `geosite-cn`, `category-ru` / `geosite-ru`; GeoIP `cn` / `geoip-cn`, `ru` / `geoip-ru`. Произвольный `.srs` и `blocked-ru` не переводятся в geo-файл Xray и возвращают `NotImplemented`; неизвестный sing-box набор также недоступен, пока для него не добавлен источник. Регистрация источника не преобразует форматы geo-файлов.

Условия: точный домен, суффикс, ключевое слово, Geosite, GeoIP, CIDR, процесс и порт; действия: через VPN, напрямую, блокировка. Порядок пользовательских правил сохраняется в обоих движках; служебные правила DNS, проверок подключения и сохранения локальных/mesh-сетей имеют приоритет. Правила по процессу доступны в sing-box только в TUN, в Xray — на Windows/Linux; неподдерживаемый вариант возвращает `NotImplemented`. В режиме привилегированного помощника внешние наборы правил по-прежнему недоступны.

### DNS в профиле подключения

На странице «Маршрутизация» можно настроить транспорт и направление запросов для двух DNS-серверов. Для выбора сервера по домену укажите суффиксы. В sing-box можно также указать теги загруженных наборов правил. FakeIP включается отдельно и работает в sing-box в режиме TUN. Исключения FakeIP получают обычные DNS-ответы.

Xray поддерживает системный DNS, UDP по IP-адресу, TCP, DoH и прямой DoQ. Для DoT, DoQ через VPN и DNS-правил с наборами используйте sing-box.

В «Настройки → Дополнительно → Активные соединения» можно раскрыть список соединений sing-box, найти соединение по домену, процессу, правилу или исходящему подключению и закрыть его. Список обновляется раз в две секунды только пока открыт этот раздел. Для Xray и остальных движков выводится сообщение о недоступности. Clash API слушает только `127.0.0.1`, с отдельным случайным секретом на каждое подключение. Из строки с доменным именем можно открыть редактор правил с заполненным условием. В режиме имитации показываются синтетические данные.

В списке подключений можно вручную запустить тест скорости для профилей sing-box и Xray на Windows, Linux и macOS. Укажите HTTPS-адрес тестового файла без учётных данных. BYDLO использует временные прокси на loopback, проверяет до двух профилей одновременно и читает до 4 МиБ на профиль. На запуск движка отведено до 12 секунд, на запрос и загрузку — ещё до 12 секунд. Если время загрузки истекло после получения части файла, скорость рассчитывается по полученным байтам. Ответ запрашивается без сжатия и с запретом кеширования; перенаправления не выполняются. Это короткая оценка скорости загрузки, а не гарантия пропускной способности.

Перед запуском показано предупреждение о расходе трафика. Результат отображается в строке сервера; доступна сортировка по убыванию скорости. Ошибки и неподдерживаемые профили отображаются как «—». Произвольные JSON-конфиги исключены: их правила могут направлять запрос напрямую или через несколько серверов. Профили других движков (например, OpenVPN и AmneziaWG), цепочки и инструменты Zapret / Telegram этим тестом не измеряются. WireGuard измеряется только через локальный прокси sing-box, если он выбран для профиля.

При отмене временные движки останавливаются независимо от отменённого токена. Ошибка очистки сообщается пользователю; менеджер сохраняет движок и рабочие файлы для повторной очистки при завершении работы. В Mock Mode и под блокировкой разработки замер отключён с пояснением в интерфейсе. Реальные сетевые проверки выполняет только сопровождающий вручную.

В редакторе профиля можно переопределить общие настройки фрагментации TLS, padding и мультиплексирования. sing-box поддерживает фрагментацию ClientHello или записей TLS и padding внутри mux. Для фрагментации ClientHello sing-box использует верхнюю границу интервала как резервную задержку, а размер определяет сам. Xray поддерживает размер и интервал фрагментации ClientHello, padding для XHTTP и XUDP. Мультиплексирование с Vision отклоняется.

В macOS секреты сохраняются в Keychain, в Linux — в Secret Service через libsecret. При первом чтении старые записи переносятся из зашифрованных файлов. Если системное хранилище недоступно, локальные записи продолжают работать, а в настройках появляется предупреждение. Для доступа к уже перенесённой записи нужно разблокировать системное хранилище. Резервная копия использует то же хранилище через общий интерфейс.

Файловая копия заменяется служебной отметкой только после успешной записи и проверки чтения из системного хранилища. Если перенесённый секрет удалён из Keychain / Secret Service, приложение сообщает об этом и предлагает восстановить резервную копию или повторить импорт. Резервное копирование при недоступных перенесённых секретах завершается ошибкой, чтобы не создать неполную копию без предупреждения. Разные каталоги данных используют отдельные записи системного хранилища. В Linux нужны `libsecret-1.so.0` и работающий Secret Service в пользовательской D-Bus-сессии; при их отсутствии новые и ещё не перенесённые секреты остаются в зашифрованных файлах. В безопасном режиме разработки и при принудительном `--mock` системное хранилище не используется.

Выбор хранилища, миграция существующих AES-файлов, недоступность и отмена операций, удаление и резервное копирование проверяются изолированными тестами с фейками. Реальная работа Keychain и Secret Service требует ручной проверки на соответствующих ОС.

При локальном подключении BYDLO может настроить системный HTTP/HTTPS-прокси в Windows, GNOME, KDE и macOS. В GNOME и KDE нужны штатные инструменты рабочего стола. В macOS используются активные сетевые службы. Linux и macOS сохраняют предыдущие параметры в журнале и восстанавливают их при отключении или после сбоя. Настройки, изменённые другим приложением во время подключения, сохраняются.

Clash/Mihomo YAML импортируется как список отдельных профилей VLESS, VMess, Trojan, Shadowsocks, Hysteria2 и TUIC. Предпросмотр показывает номера пропущенных записей. В пользовательских JSON sing-box и Xray BYDLO сохраняет исходящие подключения и поддерживаемые встроенные правила. Слушатели, режим TUN и служебный API задаёт BYDLO. Настройки с внешними файлами и пользовательским API отклоняются. JSON с учётными данными хранится в хранилище секретов.

Для Clash сохраняются списки HTTP/H2-хостов и ограничения скорости Hysteria2 (`up` / `down`, целые Мбит/с или `50 Mbps`); `hy2` распознаётся как Hysteria2. JSON проверяется до предпросмотра: обязательные адреса, числовые порты 1–65535, учётные данные и форма основных параметров исходящих подключений. Это проверка поддерживаемого подмножества, а не полная схема всех версий движков. TUN пользовательского JSON поддерживает sing-box; Xray использует локальный прокси.

Публичные списки igareck доступны в мастере «Добавить сервер». BYDLO запрашивает список при выборе источника, пробует зеркала по очереди и показывает распознанные и пропущенные записи. Повторяющиеся параметры подключения и учётные данные в пределах одного списка объединяются. После подтверждения сохраняется подписка с адресом ответившего зеркала. Состав списков меняется. Публичными серверами управляют сторонние владельцы.

При обновлении подписки совпавшие узлы сохраняют ID, имя, избранное, выбор движка и локальные параметры. Изменения поставщика применяются к параметрам, которые пользователь не переопределял. При первом обновлении старых подписок без исходного снимка BYDLO сохраняет текущие параметры узлов. BYDLO сопоставляет протокол, адрес, порт и учётные данные. Для нескольких узлов с одинаковыми данными учитываются параметры подключения. Исчезнувшие из списка узлы остаются, если они в избранном или в цепочке. Если сохранённый адрес публичного списка недоступен, BYDLO пробует другие зеркала того же источника.
